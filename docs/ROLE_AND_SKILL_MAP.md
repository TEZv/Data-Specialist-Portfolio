# Role and skill map

## Data Analytics

Primary question: **What happened, why, and what should the business do?**

Universal skills:

- KPI and business logic;
- exploratory and diagnostic analysis;
- product funnels, retention, churn and monetization;
- statistics and experimentation;
- dashboards and communication;
- SQL, spreadsheets and Python for analysis.

Portfolio evidence: TaskFlow and professional media reporting context.

## Analytics Engineering

Primary question: **Can analysts and business users trust and reuse the data model and metrics?**

Universal skills:

- transformation layers and stable grain;
- metric definitions and semantic consistency;
- data modeling for reporting;
- tests, freshness and reconciliation;
- documentation and lineage;
- Git/CI for analytical changes;
- SQL-first delivery, often with dbt.

Portfolio evidence: professional reporting automation patterns plus the media mart implementation.

## Data Engineering

Primary question: **Can data be ingested, stored, processed and operated reliably at the required scale?**

Universal skills:

- SQL and Python;
- relational and dimensional modeling;
- ETL/ELT and incremental processing;
- orchestration and retry/idempotency;
- data quality and observability;
- performance, security and cost control;
- CI/CD, cloud and Infrastructure as Code;
- operational ownership and incident response.

Portfolio evidence: MS SQL development, maintenance/reliability and Azure SQL Terraform.

## Where Databricks fits

Databricks is a **platform specialization**, not a replacement for the universal skills above. A credible Databricks increment should demonstrate:

- PySpark transformations;
- Delta Lake tables and `MERGE`;
- bronze/silver/gold layers;
- schema evolution and data-quality expectations;
- incremental jobs and retries;
- query/job cost and performance reasoning;
- Unity Catalog/governance concepts where available.

Current evidence and next learning gates:

1. SQL Server portfolio: CI-verified development, data modelling, maintenance and assertions. Continue practising SQL independently for interview fluency.
2. Python: used in independent pipeline/validation labs; build core-language fluency through small edits and tests.
3. Airflow and Kafka: implemented lab modules with CI evidence; personal interview readiness still needs walkthroughs and independent changes.
4. Azure ERP → DWH: Terraform, ADF definitions, SQL star model and tests are present. Azure apply, identity grants, endpoint approval and alert delivery remain unverified.
5. Databricks-compatible PySpark/Delta Lake pipeline: Bronze/Silver/Gold, schema evolution, `MERGE`, quarantine and tests are implemented; an actual Databricks workspace run remains unverified.

This is a technical evidence map, not a claim of commercial tenure or independent fluency in every listed platform.
