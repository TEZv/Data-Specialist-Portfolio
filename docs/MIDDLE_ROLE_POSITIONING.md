# 🎯 Middle-level role positioning

## Target

This portfolio is positioned for **Middle Data Analyst**, **Analytics Engineer**, and **Middle Data Engineer** opportunities where a candidate is expected to take an ambiguous data need through design, implementation, verification and documentation.

## What demonstrates middle-level scope

| Middle-level expectation | Portfolio evidence |
|---|---|
| Translate a business need into a data design | KPI/reporting automation context, TaskFlow case, ERP and lakehouse scenarios |
| Own a data model and transformations | Relational model, SCD2, Silver/Gold layers and reporting views |
| Engineer for correctness, not only a happy path | Validation, quarantine, reconciliation, idempotency and late-arriving data handling |
| Deliver repeatably | Docker/SQL integration tests, PySpark/Delta CI and Terraform validation |
| Operate and explain the solution | Maintenance procedures, incident runbooks, evidence maps and interview stories |
| Communicate scope honestly | Explicit separation of professional, independent and learning evidence |

## Application language

Use this in recruiter-facing summaries:

> **Data & Analytics Engineer — Middle-level portfolio.** I combine commercial analytics and reporting-automation experience with independently built, CI-validated SQL Server and PySpark/Delta Lake data platforms. I design reliable transformations, data-quality controls and documented delivery paths from business requirements to usable data products.

## Honest boundary

“Middle-level portfolio” describes the scope and quality of the demonstrated work. It does not rewrite a formal employment title, invent client engagements, or claim commercial tenure with technologies that were used only in independent projects. For roles that contractually require a specific number of commercial years in a named platform, disclose that distinction directly.
